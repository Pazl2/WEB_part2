# Платформа для обмена опытом между дальнобойщиками

Лабораторная работа №6. Интеграция с NoSQL базой данных MongoDB. Ветка репозитория: `lab26`.

Сервер: Node.js + Express + JWT (с двухфакторным подтверждением входа). Две базы данных:

- **PostgreSQL (Sequelize)** — пользователи;
- **MongoDB (Mongoose)** — посты (с тегами и вложенными комментариями).
Клиент: React + Vite + axios (папка `euroTruck`): теги постов (фильтр по клику), комментарии с лайками, добавлением и удалением.

В этой ветке посты перенесены из PostgreSQL в MongoDB, а пользователи остаются в PostgreSQL (ветка `lab25` с полностью PostgreSQL остаётся без изменений).

## Требования

- Node.js 20+
- PostgreSQL (пользователи)
- MongoDB Atlas (бесплатный кластер M0) или локальный MongoDB Community Edition (посты)

## Запуск сервера

```bash
npm install
cp .env.example .env     # затем впишите JWT_SECRET, MONGO_URI и данные PostgreSQL
npx sequelize-cli db:migrate   # таблица Users, защита 2FA, username (при обновлении запустите обязательно)
npm run migrate:authors -- --dry-run   # только при обновлении: что изменится в MongoDB (без записи)
npm run migrate:authors        # заменяет email в author старых постов и комментариев на username
npm run seed             # (необязательно) демо-посты с тегами и комментариями в MongoDB
npm run dev
```

В `.env`:

- `MONGO_URI` — строка подключения (Atlas: `mongodb+srv://<user>:<password>@<cluster>.mongodb.net/euroTruck?...`,
  локально: `mongodb://127.0.0.1:27017/euroTruck`). Если в пароле есть спецсимволы, закодируйте их (`@` → `%40`).
  В Atlas: Network Access → добавить свой IP (или `0.0.0.0/0` для учебных целей).
- `DB_USERNAME`, `DB_PASSWORD`, `DB_NAME`, `DB_HOST`, `DB_PORT`, `DB_DIALECT` — подключение к PostgreSQL (пользователи).
- `JWT_SECRET` — **обязателен**. Сервер не запустится, если секрет пустой, короче 32 символов, предсказуемый или скопирован из примера. Сгенерировать:
  `node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"`. Если секрет из старого `.env.example` где-то использовался, считайте его скомпрометированным и замените.
- `JWT_EXPIRES_IN` — срок жизни токена (`15m`, `1h`, `12h`), по умолчанию `1h`, максимум `24h`: токен нельзя отозвать до истечения, поэтому его срок держат коротким.
- `CLIENT_ORIGIN` — адрес клиента, которому разрешён доступ к API (CORS), можно несколько через запятую. В разработке по умолчанию `http://localhost:5173`, в production (`NODE_ENV=production`) обязателен.
- `TRUST_PROXY` — нужен только за reverse proxy (число прокси, обычно `1`), иначе rate limit будет считать все запросы с одного IP.
- `PORT`, `RESPONSE_DELAY_MS` — как в предыдущих работах.

Сервер доступен по адресу `http://localhost:3000`, API — по префиксу `/api`.

## Модель данных

**PostgreSQL**, таблица `Users`: `id` (integer, автоинкремент), `email` (уникальный, наружу не отдаётся), `username` (публичное имя, уникально без учёта регистра), `password` (bcrypt), `role`, `twoFactorCode` (HMAC кода, а не сам код), `twoFactorExpires`, `twoFactorAttempts`, `twoFactorLockedUntil`, `createdAt`, `updatedAt`.

**MongoDB**, коллекция `posts` (документ):

```js
{
  _id, title, content, author, category,
  tags: ['граница', 'важный'],                       // массив строк
  comments: [{ _id, author, text, likes, createdAt }], // вложенные документы
  userId: 1,                                         // id пользователя из PostgreSQL (Users.id)
  createdAt, updatedAt
}
```

Между базами нет внешнего ключа, поэтому связь `posts.userId → Users.id` поддерживается в коде:

- при выдаче постов `username` автора подтягивается одним запросом к PostgreSQL (аналог `populate`) и добавляется в ответ как `user: { id, username }`. Email в публичных ответах не отдаётся нигде: ни в постах, ни в комментариях;
- при удалении пользователя (`DELETE /api/users/:id`) из MongoDB вручную удаляются его посты, его комментарии в чужих постах и его лайки под чужими комментариями (счётчик `likes` корректируется). Удаление пользователя выполняется в транзакции PostgreSQL: если любой шаг в MongoDB не удался, пользователь остаётся. Шаги идемпотентны, повторный запрос доделает остальное.

В реляционной версии комментарии и теги потребовали бы отдельных таблиц и JOIN; здесь это один документ.

## Эндпоинты API

| Метод | URL | Доступ | Описание |
| --- | --- | --- | --- |
| GET | `/api/posts` | открытый | Страница постов. Параметры: `search` (заголовок, текст, автор), `tag`, `category`, `sort=new\|old`, `page` (с 1), `limit` (1–50, по умолчанию 10). Ответ: `{ items, total, page, limit, totalPages, categoryCounts }`, где `categoryCounts` — число постов по категориям при текущих `search` и `tag` |
| GET | `/api/posts/:id` | открытый | Один пост (с комментариями) |
| POST | `/api/posts` | JWT | Добавление поста (`title`, `content`, `category`, `tags`). Автор (`username`) и владелец берутся из учётной записи. Не более 10 постов за 10 минут на пользователя |
| PUT | `/api/posts/:id` | JWT, автор поста или admin | Редактирование поста (`author` и владелец не меняются) |
| DELETE | `/api/posts/:id` | JWT, автор поста или admin | Удаление поста, в ответе — удалённый документ |
| POST | `/api/posts/:id/comments` | JWT | Добавить комментарий во вложенный массив (`{ "text": "..." }`, до 500 символов; не более 500 комментариев в посте, `409` при превышении; не более 30 комментариев за 10 минут на пользователя) |
| PUT | `/api/posts/:id/comments/:commentId/like` | JWT | Поставить лайк (один пользователь — один лайк, повтор ничего не меняет) |
| DELETE | `/api/posts/:id/comments/:commentId/like` | JWT | Снять свой лайк |
| DELETE | `/api/posts/:id/comments/:commentId` | JWT, автор комментария или admin | Удалить комментарий из массива (`$pull`) |
| DELETE | `/api/users/:id` | JWT + admin | Удалить пользователя (PostgreSQL) и каскадно все его посты (MongoDB) |
| POST | `/api/auth/register` | открытый | Регистрация (`email`, `username`, `password`). Пароль: от 8 символов, не более 72 байт; email не длиннее 254 символов; username: 3–24 символа (буквы, цифры, `_`, `-`), уникален без учёта регистра, имена вроде `admin` зарезервированы |
| POST | `/api/auth/login` | открытый | Проверка пароля, генерация кода подтверждения |
| POST | `/api/auth/verify-2fa` | открытый | Проверка кода, выдача JWT-токена и данных пользователя `{ id, email, role }` |
| GET | `/api/auth/me` | JWT | Данные текущего пользователя |

Чтобы получить права admin, в PostgreSQL выполните `UPDATE "Users" SET role = 'admin' WHERE email = 'ваш@email';` и заново войдите.

## Права доступа

Права проверяет сервер (кнопки, скрытые на клиенте, защитой не являются):

- Токен проверяется при каждом запросе, а `id`, `email` и `role` берутся из PostgreSQL, а не из токена. Удалённый пользователь или смена роли действуют сразу.
- Просроченный или недействительный токен — `401` (клиент выходит из аккаунта). Нет прав на действие — `403` (клиент только показывает сообщение).
- Пост редактирует и удаляет его автор или `admin`. Автор поста (`author`) и владелец (`userId`) задаются сервером и из запроса не принимаются.
- Комментарий удаляет его автор или `admin`. Автор комментария — всегда текущий пользователь.
- Лайк: один пользователь — один лайк на комментарий (`likedBy` + атомарный апдейт), лайк можно снять.
- Старые и демо-записи без `userId` (в том числе из `npm run seed`) может менять и удалять только `admin`.

## Вход в приложение

1. Нажмите «Регистрация», введите email, имя пользователя (оно показывается как автор постов и комментариев) и пароль (минимум 8 символов, максимум 72 байта: кириллица занимает по 2 байта).
2. Введите те же email и пароль, нажмите «Получить код».
3. Скопируйте шестизначный код из консоли сервера (`[2FA] Код подтверждения ...`), введите его и подтвердите.
4. JWT-токен сохраняется в `localStorage` и подставляется в запросы через axios interceptor.

## Защита входа

- Код 2FA — шесть цифр из `crypto.randomInt`, живёт 5 минут, одноразовый. В БД лежит его HMAC (ключ выводится из `JWT_SECRET`), а не сам код.
- Неверный ввод кода считается. После 5 неверных подряд код аннулируется, а вход по коду блокируется на 15 минут (`429`). Счётчик ведётся в транзакции с блокировкой строки, поэтому параллельными запросами его не обойти. Код неверного формата (не 6 цифр) в счётчик не входит.
- Rate limit по IP на `/api/auth/*`: регистрация 10 в час, вход 10 за 15 минут, проверка кода 10 за 15 минут. При превышении — `429` и заголовки `RateLimit-*`/`Retry-After`. Счётчики живут в памяти процесса и сбрасываются при перезапуске.
- JWT подписывается и проверяется только алгоритмом `HS256`; в токене лежит один `id`, а роль и email сервер берёт из БД при каждом запросе.
- CORS открыт только для `CLIENT_ORIGIN`; добавлены заголовки безопасности (`helmet`) и лимит тела запроса 100 КБ.
- Пароли пользователей, зарегистрированных до введения правил, остаются рабочими. Требования проверяются только при регистрации.

## Валидация и лимиты

Все проверки выполняет сервер (`config/limits.js`), слишком длинные данные отклоняются с `400`, а не обрезаются молча:

- `category` — одна из: Общее, Границы, Стоянки, Дороги;
- `title` до 150 символов, `content` до 10000, не более 10 тегов по 30 символов, комментарий до 500 символов;
- не более 500 комментариев в посте (проверка выполняется в условии того же атомарного запроса, который добавляет комментарий);
- создание постов и комментариев ограничено по частоте на пользователя (`429`);
- идентификатор в `/api/users/:id` должен помещаться в int32, иначе `400`, а не ошибка БД.

Пользователям, зарегистрированным до появления `username`, миграция выдаёт имя `user<id>`. Смена имени пока не реализована.

cd euroTruck

Клиент открывается по адресу `http://localhost:5173` (`VITE_API_URL=http://localhost:3000/api`).

## Что добавлено в клиент (лаб. 6)

- Поле «Автор» из формы убрано: автором становится вошедший пользователь.
- Кнопки «Редактировать» и «Удалить» у постов и «Удалить» у комментариев видны только автору и админу; лайк комментария — переключатель с отметкой «мой лайк».
- В форме поста — поле «Теги через запятую»; теги выводятся под текстом поста, клик по тегу фильтрует ленту (`GET /api/posts?tag=...`), фильтр сбрасывается крестиком.
- Под каждым постом — раскрывающийся блок комментариев: список, лайк (`PUT`/`DELETE .../like`), добавление и удаление своего комментария. Писать и лайкать могут только авторизованные пользователи.
- Лента загружается постранично (по 10 постов, кнопки «Назад» и «Вперёд»). Поиск, категория и сортировка выполняются на сервере, а счётчики категорий приходят в ответе (`categoryCounts`). Любая смена фильтра возвращает на первую страницу.
- В форме регистрации появилось поле «Имя пользователя». В шапке и под постами показывается оно, а не email.
